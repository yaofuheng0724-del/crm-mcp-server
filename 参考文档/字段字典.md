项目查询入口统一用：

```graphql
projectInfo(id: "CRM项目ID")
```

请求固定是：

```http
POST http://api.in.chaitin.net/crm/query
```

**0. 客户查询与伙伴查询**

这部分用于补充“查客户归属”和“查伙伴归属”的接口与字段口径。

- 客户归属查询和伙伴归属查询在 API 层面已开放。
- 它们不是单独命名为“归属查询”的独立接口，而是通过客户/伙伴查询接口返回归属字段。
- 客户列表类接口和客户归属查询不是同一口径：
  - `list_all_company` 可用于开放查询客户归属。
  - `listCompany` 属于客户列表查询，结果受权限范围影响。

**0.1 客户查询**

可用入口：

- `list_all_company(search: CompanySearchParam!, pagination: PaginationParam): CompanyLiteConnection`
- `listCompany(search: [CompanySearchParam!], pagination: PaginationParam): CompanyConnection`
- `companyInfo(id: ID!): Company!`
- `find_company_or_high_seas_company_by_id(id: ID!): Company`

按客户名查询时，常用搜索条件：

- `search.name: [String!]`

客户归属相关字段：

- `客户ID`：`list_all_company.data[].id` / `listCompany.data[].id`
- `客户名`：`list_all_company.data[].name` / `listCompany.data[].name`
- `客户简称`：`list_all_company.data[].common_name` / `listCompany.data[].common_name`
- `客户所属区域`：`list_all_company.data[].region.name` / `listCompany.data[].region.name`
- `客户所属省份/区域组`：`list_all_company.data[].region.group` / `listCompany.data[].region.group`
- `客户所属国家`：`list_all_company.data[].country.name` / `listCompany.data[].country.name`
- `客户负责人`：`list_all_company.data[].claim_by.name` / `listCompany.data[].claim_by.name`
- `客户负责人用户名`：`list_all_company.data[].claim_by.username` / `listCompany.data[].claim_by.username`
- `客户所属组`：`list_all_company.data[].claim_by_group.name` / `listCompany.data[].claim_by_group.name`
- `客户所属业务单元`：`list_all_company.data[].claim_by_group.parent.name` / `listCompany.data[].claim_by_group.parent.name`
- `客户所属业务单元兜底`：`list_all_company.data[].first_group_name` / `listCompany.data[].first_group_name`
- `客户等级`：`list_all_company.data[].rank` / `listCompany.data[].rank`

说明：

- `claim_by` 可能为空，但 `claim_by_group` 和 `first_group_name` 仍可能有值。
- 当只想查客户归属时，优先使用 `list_all_company`。
- `listCompany` 即使接口可调用，也可能因权限范围返回 `total = 0`。

已验证示例：

- 查询 `中国电力建设企业协会`
  - `list_all_company` 返回 1 条，能看到 `claim_by_group = 能源组`，`first_group_name = 能源央企头部战队`
  - `listCompany` 返回 0 条
- 查询 `山东东知信息技术有限公司`
  - `region.name = 日照市`
  - `region.group = 山东省`

**0.2 伙伴查询**

可用入口：

- `listChannel(search: ChannelSearchParam!, pagination: PaginationParam, with_perm: Boolean!): ChannelConnection`
- `channel(id: ID!): Channel!`

按伙伴名查询时，常用搜索条件：

- `search.name: [String!]`

伙伴归属相关字段：

- `伙伴ID`：`listChannel.data[].id`
- `伙伴名`：`listChannel.data[].name`
- `伙伴简称`：`listChannel.data[].common_name`
- `伙伴地区`：`listChannel.data[].region.name`
- `伙伴销售负责人`：`listChannel.data[].sale_claim_by.name`
- `伙伴销售负责人用户名`：`listChannel.data[].sale_claim_by.username`
- `伙伴记录所属组`：`listChannel.data[].sale_claim_by_group.name`
- `伙伴记录所属一级战队`：`listChannel.data[].sale_claim_by_group.parent.name`
- `伙伴记录所属一级战队兜底`：`listChannel.data[].sale_claim_by_first_group.name`
- `伙伴运营负责人`：`listChannel.data[].channel_sale_claim_by.name`
- `伙伴运营负责人用户名`：`listChannel.data[].channel_sale_claim_by.username`

负责人当前组织字段：

- `伙伴销售负责人当前用户组`：`listChannel.data[].sale_claim_by.usergroup[].name`
- `伙伴销售负责人当前上级组`：`listChannel.data[].sale_claim_by.usergroup[].parent.name`
- `伙伴运营负责人当前用户组`：`listChannel.data[].channel_sale_claim_by.usergroup[].name`
- `伙伴运营负责人当前上级组`：`listChannel.data[].channel_sale_claim_by.usergroup[].parent.name`

说明：

- `sale_claim_by_group` / `sale_claim_by_first_group` 是伙伴记录上保存的归属字段。
- `sale_claim_by.usergroup[]` 是负责人用户当前所在组织。
- 两者不是同一口径，可能不一致，不能混用。

已验证示例：

- 查询 `北京禹宏信安科技有限公司`
  - 伙伴销售负责人：`李智`
  - 伙伴记录所属组：`其他`
  - 伙伴记录所属一级战队：`政府头部战队`
  - 李智当前用户组：`北区伙伴拓展组`
  - 李智当前上级组：`伙伴管理部`
  - 因此“伙伴记录归属”和“负责人当前组织”要分开解释

**0.3 客户与伙伴查询模板**

客户归属查询：

```bash
curl -X POST 'http://api.in.chaitin.net/crm/query' \
  -H "Authorization: Bearer $CRM_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"query":"query($search: CompanySearchParam!, $pagination: PaginationParam!) { list_all_company(search: $search, pagination: $pagination) { total skip limit data { id name common_name region { id name group country_id } country { id name } claim_by { id name username } claim_by_group { id name parent { id name } } first_group_name rank created_at updated_at } } }","variables":{"search":{"name":["客户名"]},"pagination":{"skip":0,"limit":20}}}'
```

客户列表查询：

```bash
curl -X POST 'http://api.in.chaitin.net/crm/query' \
  -H "Authorization: Bearer $CRM_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"query":"query($search: [CompanySearchParam!], $pagination: PaginationParam!) { listCompany(search: $search, pagination: $pagination) { total skip limit data { id name common_name region { id name group country_id } country { id name } claim_by { id name username } claim_by_group { id name parent { id name } } first_group_name rank created_at updated_at } } }","variables":{"search":[{"name":["客户名"]}],"pagination":{"skip":0,"limit":20}}}'
```

伙伴归属查询：

```bash
curl -X POST 'http://api.in.chaitin.net/crm/query' \
  -H "Authorization: Bearer $CRM_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"query":"query($search: ChannelSearchParam!, $pagination: PaginationParam!, $withPerm: Boolean!) { listChannel(search: $search, pagination: $pagination, with_perm: $withPerm) { total skip limit data { id name common_name status type region { id name } sale_claim_by { id name username usergroup { id name parent { id name } } } sale_claim_by_group { id name parent { id name } } sale_claim_by_first_group { id name } channel_sale_claim_by { id name username usergroup { id name parent { id name } } } } } }","variables":{"search":{"name":["伙伴名"]},"pagination":{"skip":0,"limit":20},"withPerm":false}}'
```

**1. 项目卡点类**

- `crm_id`：`projectInfo.id`
- `项目名`：`projectInfo.name`
- `客户名`：`projectInfo.company.name`
  - 这是基于 `company: CompanyLite` 的推断，极大概率可用；若报错，再查 `CompanyLite` 字段
- `项目要素整体状态`：`projectInfo.project_element_status`
- `要素名称`：`projectInfo.element_list[].element.name`
- `方向`：`projectInfo.element_list[].element.direction`
- `方向状态`：`projectInfo.direction_list[].stuck_point_status`
  - 需要按 `element_list[].element.direction = direction_list[].direction` 关联
- `要素是否完成`：`projectInfo.element_list[].is_finished`
- `卡点备注`：`projectInfo.element_list[].stuck_point_note`
- `目标备注`：`projectInfo.element_list[].target_note`
- `卡点详细内容`：`projectInfo.element_list[].stuck_point_list[].other_name`
- `卡点是否完成`：`projectInfo.element_list[].stuck_point_list[].is_finished`
- `卡点名称`：`projectInfo.element_list[].stuck_point_list[].stuck_point.name`
- `卡点配置是否下线`：`projectInfo.element_list[].stuck_point_list[].stuck_point.is_offline`
- `要素配置序号`：`projectInfo.element_list[].element.index`
- `要素配置是否下线`：`projectInfo.element_list[].element.is_offline`

**2. 项目跟进记录类**

- `crm_id`：`projectInfo.id`
- `项目名`：`projectInfo.name`
- `客户名`：`projectInfo.company.name`
- `记录ID`：`projectInfo.infos[].id`
- `记录类型`：`projectInfo.infos[].type`
- `跟进类型`：`projectInfo.infos[].follow_type`
- `来源`：`projectInfo.infos[].origin`
- `跟进内容`：`projectInfo.infos[].info`
- `创建时间`：`projectInfo.infos[].created_at`
- `更新时间`：`projectInfo.infos[].updated_at`
- `记录人ID`：`projectInfo.infos[].creator.id`
- `记录人用户名`：`projectInfo.infos[].creator.username`
- `记录人姓名`：`projectInfo.infos[].creator.name`

**3. 项目信息类**

- `crm_id`：`projectInfo.id`
- `项目名`：`projectInfo.name`
- `客户名`：`projectInfo.company.name`
- `项目阶段`：`projectInfo.stage`
  - 当前建议映射为中文展示值：
    - `leads` -> `销售线索`
    - `confirmed` -> `商机阶段1：需求挖掘`
    - `tech_pre_research` -> `商机阶段2：技术预研`
    - `plan_discuss` -> `商机阶段3：方案论证`
    - `project_approval` -> `商机阶段4：立项审批`
    - `start_purchase` -> `商机阶段5：启动采购`
    - `business_tender` -> `商机阶段6：商务招标`
    - `recognized` -> `商机阶段7：签单冲刺`
    - `deal` -> `合同签署`
    - `invalid` -> `失效`
    - `lost_order` -> `丢单`
- `预估合同签署日期`：`projectInfo.sign_date`
  - 当前口径明确用 `sign_date`
  - 不再以 `estimated_sign_date` 作为默认取值
- `项目承诺`：`projectInfo.project_promise`
  - 当前建议映射为中文展示值：
    - `must_sign` -> `必签`
    - `focus_strive_for` -> `重点争取`
    - `strive_for` -> `争取`
    - `take_part_in` -> `参与`
- `赢单率`：`projectInfo.win_rate`
  - 当前返回形态是带 `%` 的字符串，例如 `25%`
- `销售主负责人`：`projectInfo.claimBy.user.name`
  - 这是项目维度的主负责人
  - 一个项目按当前业务口径一定有销售主负责人
- `销售所属组`：`projectInfo.claimBy.user.usergroup[0].name`
  - 跟随项目主负责人所在组
- `销售所属业务单元`：`projectInfo.claimBy.user.usergroup[0].parent.name`
  - 跟随项目主负责人所在组的上一级业务单元
- `客户负责人`：`projectInfo.company.claim_by.name`
  - 这是客户维度负责人，不等于项目主负责人
  - 通常和项目主负责人一致，但不能混用
- `客户所属组`：`projectInfo.company.claim_by_group.name`
- `客户所属业务单元`：`projectInfo.company.claim_by_group.parent.name`
  - 若客户负责人为空，仍可用客户归属组链路取业务单元
- `客户所属业务单元兜底`：`projectInfo.company.first_group_name`
  - 这是客户维度的业务单元展示兜底字段
- `项目关联的商品`：`projectInfo.products[].product.name`
  - 一个项目可能关联多个商品，建议保留为数组或多值字段

建议关注的 `infos.type`：
- `project_follow_record`：项目跟进记录
- `company_background`：客户背景信息

```bash
curl -X POST 'http://api.in.chaitin.net/crm/query' \
  -H "Authorization: Bearer $CRM_TOKEN" \
  -H 'Content-Type: application/json' \
```


**扁平化规则**

**A. 卡点明细表**
一行代表“一条要素下的一条卡点”。

输出列建议：

- `crm_id`
- `项目名`
- `客户名`
- `项目要素整体状态`
- `要素ID`
- `要素名称`
- `方向`
- `方向状态`
- `要素是否完成`
- `卡点备注`
- `目标备注`
- `卡点ID`
- `卡点名称`
- `卡点详细内容`
- `卡点是否完成`
- `卡点配置是否下线`

规则：

1. 先遍历 `element_list`
2. 用 `element.direction` 去匹配 `direction_list.direction`，取 `stuck_point_status` 作为方向状态
3. 再遍历该要素的 `stuck_point_list`
4. 如果 `stuck_point_list` 非空：每条 `stuck_point_list` 输出一行
5. 如果 `stuck_point_list` 为空，但 `stuck_point_note` 非空：仍输出一行，卡点相关字段置空，仅保留备注
6. 如果两者都空：可选
   - 保留一行表示“该要素当前无卡点”
   - 或跳过，取决于你的报表口径

**B. 跟进记录表**
一行代表一条 `infos` 记录。

输出列建议：

- `crm_id`
- `项目名`
- `客户名`
- `记录ID`
- `记录类型`
- `跟进类型`
- `来源`
- `跟进内容`
- `创建时间`
- `更新时间`
- `记录人ID`
- `记录人用户名`
- `记录人姓名`

规则：

1. 遍历 `infos`
2. 若只要项目跟进，筛 `type = "project_follow_record"`
3. 若还想保留客户背景，额外保留 `type = "company_background"`
4. `info` 原样保留；后续如需结构化，可再按 `【需求】/【技术认可】` 这类段落标题二次解析

**建议口径**

- 查卡点时，优先看 `stuck_point_list[].other_name`
  - 这是“卡点详细内容”
- `stuck_point_note` 更像补充备注，不替代卡点详细内容
- `project_element_status = "nothing"` 不代表一定没有要素数据，实际仍可能有 `element_list` 和 `direction_list`
